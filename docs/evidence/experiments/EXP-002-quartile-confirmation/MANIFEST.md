Totals: 4665 NumPy evaluations; 69 non-finite outputs where the exact value is representable (the intermediate-overflow defect of review blocker 1, all in F4).

Findings:
1. **The EXP-001 revised criterion (<= 1 operand-scale ulp) was falsified on held-back data**: NumPy reached 1.125 operand-scale ulp in F1 (2 evaluations) and F5 (1 evaluation). The criterion had been chosen after seeing the failure on the same data and was not derived tightly; this confirmation set shows it was too tight for NumPy's lerp.
2. The **first-order derived bound (4 operand-scale ulp)** held: 0 violations in every family. This supports the derivation but is not a guarantee beyond these data.
3. The **original criterion (<= 2 ulp of the result)** failed again, by far more than in EXP-001 (up to 1,048,576 ulp of the result in the cancellation families), confirming that result-relative ulp is the wrong metric for lerp-based interpolation under cancellation.
4. NumPy produced non-finite outputs for 69 evaluations whose exact values are representable; the exact implementation produced none.
5. These measurements concern NumPy, which is **no longer used in production**; production quartiles are exact values rounded once, and C1 holds on all 8,000 evaluations.

## Limitations and failures
- One machine, one run; the oracle was written by the same implementer and shares the *definition* of type 7 with production (different arithmetic formulation, no shared code); not independently reviewed or reproduced.
- Seeds and families were fixed before the run, but are still generated data; 'confirmed' means no counterexample in these 8,000 evaluations, not a proof. A formal argument for correct rounding rests on the exactness of rational arithmetic and on `Fraction.__float__` rounding once.
- The EXP-001 quartile criteria are recorded as originally written. The criterion falsified here is listed in ADR 0004 (amendment).
- Mean was evaluated for the underflow policy; variance/SD were not part of this experiment.
