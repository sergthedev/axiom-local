# EXP-008 pre-registration: AXBENCH v0.1-draft audit and the bilingual rule baseline on validation

- Issue: #4 (Phase 3A: AXBENCH and Guard). Written and committed **before** the run below, in the same commit as
  the code and corpus under test (the script records `git.commit`).
- Rule router `axiom.rules/0.1` (`src/axiom_router/rules.py`) is frozen at this commit. It was developed by the
  implementing AI tool on the **train** split only (400 examples; the last development run gave 400 of 400 semantic
  exact matches on train, which shows template learnability, not generalization). The validation split has not been
  scored by any router before this run, as far as the session record shows. Its lexicon is built only from the
  shared schema families (`axbench.evaluate.training_lexicon`).
- Disclosure: the same tool wrote all templates, including validation and test lineages, and the rules. During
  development the rule vocabulary was checked against held-out templates by the contamination audit and 81 cues
  occurring only in held-out templates (plus a few word-list entries) were removed. That check read held-out
  template words; it never scored a router on held-out examples. The baseline is therefore not blind.
- The final test split is not generated, read or scored. The development test split exists only in memory for the
  audit (no text is written).
- If the script fails to run, the failure, the fix and the rerun are recorded; criteria are not changed. The rules are
  not changed after seeing validation results within this experiment; any later rule version is a new system whose
  validation numbers are labelled post hoc.

Command (repository root, clean tree, after `uv sync --locked`):

```bash
uv run python benchmarks/issue4_axbench_baseline.py --predictions docs/evidence/experiments/EXP-008-axbench-rule-baseline/rules_validation.jsonl > docs/evidence/experiments/EXP-008-axbench-rule-baseline/results.json
```

## Part A: corpus integrity, split audit and contamination audit (criteria)

| ID | Criterion |
|----|-----------|
| A1 | For `train.jsonl` and `validation.jsonl`, the SHA-256 of the regenerated bytes equals the committed file and the `MANIFEST.json` entry; no `test.jsonl` exists under `data/axbench/`. |
| A2 | The audit passes: valid gold labels in all three splits, no lineage or normalized text shared across splits, zero connected components spanning splits, zero cross-split pairs with 4-gram Jaccard at or above 0.8. |
| A3 | The rule-baseline contamination audit returns no finding. |

## Part R: rule baseline on validation (one run)

| ID | Criterion |
|----|-----------|
| R1 | All 160 validation examples get a prediction with status `ok`; all 160 raw outputs are valid JSON and valid `axiom.candidate/1` objects (the router emits only contract objects). |
| R2 | After the Guard layer, zero confirmations are given and the unauthorized dispatch count is zero. |

Measurements (no threshold, reported as observed): primary semantic exact match on the full denominator with the
Wilson interval (IID, illustrative) and the cluster bootstrap over lineages (2000 replicates, seed 2026); action
accuracy and per-class F1; operation and slot accuracy; clarify and reject recall and reason accuracy; false
rejection; plan coverage; selective risk; wrong executable proposals; Guard status counts; slices by language,
stratum, domain, family, gold action, operation and tag; latency as recorded (not a model latency). The train split
is scored the same way and labelled as the development reference.

Prediction (not a criterion): validation exact match clearly below the train result, lowest in the
`A_heldout_family` stratum, because the lexicon contains no concept of the held-out families.
