# EXP-004 pre-registration: fresh-process replay, mutation and malformed input

- Issue: #3. Written and committed **before** the measured run. A one-replay smoke run of the script (to check that it
  executes) was made on the uncommitted script before this file was written; its output was not kept and it is not
  part of the results.
- Code under test: the commit that contains this file (recorded by the script as `git.commit`).
- Script: `benchmarks/issue3_replay_benchmark.py --runs 20` (scenarios in `benchmarks/issue3_common.py`).

## Scenarios (ten representative operation plans, all four families)

| Dataset | Plans |
|---------|-------|
| `examples/synthetic_regions.csv` (150 rows, committed, SHA-256 `4f39a4f3cac2395df392ad93d56e59ecda3fc49636dde736c0f0aa9f946fd4ad`) | the five example plans: Inspect, Relate Pearson, Relate Spearman, Compare, Cluster (k=3) |
| `synthetic5000` (5,000 rows, generated by `synthetic_bytes()` from integers only, seed 20261126; not committed, SHA-256 recorded by the script) | Inspect (5 columns), Relate Pearson (f1, y), Relate Spearman (f2, y), Compare (segment, y), Cluster (f1, f2, f3, k=4, defaults) |

## Procedure

1. Per scenario: one fresh-process `analyze` produces the reference passport; the in-process result hash is recorded for
   comparison; then `replay(passport, data, runs=20)`: 20 new interpreters, each with a new workspace and run nonce,
   recompute from the file. Every run's outcome, result hash and timings are recorded.
2. Mutations on the example data (each: the old passport is replayed on the mutated file, then a new passport is created
   by `analyze` and replayed once):
   - M1 Inspect: `gdp_per_capita` of R001 23400.39 -> 93400.39.
   - M2 Compare: the first `Alpha` row moved to `Bravo`.
   - M3 Relate Pearson: `education_years` of R003 10.05 -> 19.05.
   - M4 Cluster: `household_income` of R001 (not a cluster feature) changed.
3. Malformed input: a short record appended to the example file; analysis attempted; the original Inspect passport replayed on it.

## Criteria (fixed now)

| ID | Criterion |
|----|-----------|
| R1 | Same environment: all 20 x 10 = 200 replays have verdict `exact_match` (byte-identical canonical result); each scenario has 1 distinct result hash, equal to the reference and to the in-process hash. Any other outcome is a failure and is reported, not retried. |
| R2 | Every replay ran in a distinct process with a distinct run nonce (20 distinct run ids per scenario). |
| R3 | In every worker the detected native pools report 1 thread and `fit_limit_probe` is `verified_single_thread`; an unverifiable BLAS is reported as such. |
| M-stale | For M1-M4 the old passport's replay has verdict `integrity_mismatch`, `mismatch = dataset`, engine error `plan_not_bound_to_dataset`. |
| M1 | New mean within 1 ulp of the exact rational mean of the parsed values (independent: `csv` module, `float`, `Fraction`); max = 93400.39; the three other numeric columns unchanged. |
| M2 | Alpha n_total decreases by 1, Bravo increases by 1, other groups unchanged. |
| M3 | New coefficient within 1e-12 of the exact rational Pearson oracle (`tests/oracles.py`), and different from the old one. |
| M4 | Dataset identity changes; the `result` block is byte-identical; the partition (membership sets) is the same. |
| M-rebind | Each new passport replays with `exact_match`. |
| X1 | The malformed file: analysis fails with a structured engine error (`record_width`); the old passport's replay is `integrity_mismatch` (dataset). |

Timings are descriptive (min, median, max of parent wall time including interpreter start, worker load and compute
time); no timing criterion. One machine; repeatability here says nothing about correctness or other platforms.
